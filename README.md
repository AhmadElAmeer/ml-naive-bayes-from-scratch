# ml-naive-bayes-from-scratch

[![CI](https://github.com/AhmadElAmeer/ml-naive-bayes-from-scratch/actions/workflows/ci.yml/badge.svg)](https://github.com/AhmadElAmeer/ml-naive-bayes-from-scratch/actions/workflows/ci.yml)

A spam filter built from the Naive Bayes formulas, with no machine-learning library. It implements the multinomial and Bernoulli variants, the tokenizer, cross-validation and the metrics. It's trained on 5,574 real SMS messages, and **gives the same answers as scikit-learn to within 10⁻¹²**, which is the evidence that the maths is right.

```
$ python3 -m nbspam predict "WINNER!! You have won a £1000 prize. Claim now: call 09061701461" "are we still on for dinner later?"
spam  P(spam) = 1.0000   WINNER!! You have won a £1000 prize. Claim now: call 09061701461
ham   P(spam) = 0.0000   are we still on for dinner later?
```

## Problem

Naive Bayes is usually the first text classifier people learn, and the first one they import from a library without understanding it. Writing it from scratch raises the questions a library hides:
- why does it work in log space?
- what does smoothing actually do?
- how do the multinomial and Bernoulli variants differ?
- is 98% accuracy good, when 87% of messages aren't spam anyway?

This project answers each one with code, tests and measurements.

## Overview

- `nbspam/text.py`: a tokenizer that turns a message into word counts. It also groups phone numbers, small numbers, prices and URLs into single tokens (`<longnum>`, `<num>`, `<money>`, `<url>`). A `Vocabulary` is built from training data only.
- `nbspam/model.py`: `MultinomialNB` (word counts) and `BernoulliNB` (word present or absent), with Laplace/Lidstone smoothing, log-space scoring, and probabilities computed with the log-sum-exp trick.
- `nbspam/evaluate.py`: TSV loading, stratified k-fold splits, and accuracy, precision, recall and F1.
- `nbspam/compare.py`: the only file that imports scikit-learn. It builds identical features and checks every score against `sklearn.naive_bayes`.
- `nbspam/experiments.py`: produces [docs/results.md](docs/results.md).

## Key features

- Both classic Naive Bayes variants, about 120 lines of plain Python for the model.
- Verified two ways: against the worked example in *Introduction to Information Retrieval* (exact textbook probabilities), and against scikit-learn on the real data.
- Honest evaluation: 5-fold stratified cross-validation, mean ± standard deviation, a majority-class baseline, and confusion counts, not just accuracy.
- Experiments on tokenization, the smoothing parameter, floating-point underflow, what the model learned, and every mistake it made.
- CLI: `evaluate`, `predict`, `report`.

## Tech stack

- Python 3.11+ standard library for everything the model does
- scikit-learn and SciPy only for the comparison check
- pytest

## How it works

Naive Bayes picks the class *c* that maximises P(c) · Π P(token | c). It assumes, naively, that tokens are independent given the class. That's false for language, but it ranks classes well anyway.

| | multinomial | Bernoulli |
|---|---|---|
| a message is | a bag of word **counts** | a set of words **present** |
| P(w \| c) | (count of w in c + α) / (all words in c + α·\|V\|) | (messages in c containing w + α) / (messages in c + 2α) |
| absent words | ignored | count as evidence: log(1 − P(w \| c)) |

Three implementation details matter:
- **Log space.** Multiplying hundreds of small probabilities underflows to `0.0`. The model adds logs instead (see experiment 4).
- **Smoothing (α).** Without it, one word never seen in spam during training would make P(spam) exactly 0, whatever else the message says.
- **Unseen words** (not in the training vocabulary) are dropped, the same as scikit-learn's `CountVectorizer` does at prediction time.

git clone https://github.com/AhmadElAmeer/ml-naive-bayes-from-scratch.git

python3 -m pip install -e ".[test]"     # the model itself needs nothing; this adds the comparison and tests

## Usage

```bash
python3 -m nbspam evaluate                               # 5-fold CV, multinomial, alpha = 1
python3 -m nbspam evaluate --model bernoulli --alpha 0.5
python3 -m nbspam evaluate --simple-tokens               # plain-word tokenizer, for comparison
python3 -m nbspam predict "Free entry! Text WIN to 80086" "running 10 min late"
python3 -m nbspam report --out docs/results.md           # all experiments (about 4 s)
```

## Results

All numbers are from [docs/results.md](docs/results.md), generated by `python3 -m nbspam report`. Data: the SMS Spam Collection, 5,574 messages, 13.4% spam (see [data/README.md](data/README.md)).

**1. Same answers as scikit-learn.** Trained on the same 4,458 messages with identical features, the largest difference in any log-likelihood was 4.5 × 10⁻¹³ (multinomial) and 1.7 × 10⁻¹³ (Bernoulli). That's floating-point rounding, and every prediction on the 1,116 test messages was identical.

**2. Quality (5-fold cross-validation):**

| model | tokenizer | accuracy | precision | recall | F1 | ham marked spam | spam missed |
|---|---|---:|---:|---:|---:|---:|---:|
| always say "ham" | — | 0.866 | — | 0.000 | 0.000 | 0 | 747 |
| multinomial | plain words | 0.987 | 0.972 | 0.929 | 0.950 | 20 | 53 |
| multinomial | + number/price/URL tokens | 0.988 | 0.960 | **0.950** | **0.955** | 30 | **37** |
| Bernoulli | plain words | 0.979 | 0.994 | 0.846 | 0.914 | 4 | 115 |
| Bernoulli | + number/price/URL tokens | 0.985 | **0.994** | 0.893 | 0.941 | **4** | 80 |

What this shows:

- **Accuracy alone is misleading here.** Labelling everything "ham" already scores 86.6% while catching no spam at all. Precision and recall are the numbers that matter.
- **The tokenizer was worth more than the choice of model's settings.** Grouping all long numbers into one `<longnum>` token (phone numbers like `09061701461` are each unique, but together they're the strongest spam signal) cut missed spam from 53 to 37 for multinomial, and from 115 to 80 for Bernoulli. The price: 10 more real messages flagged by the multinomial model.
- **The two variants make different trade-offs.** Bernoulli flagged only 4 real messages as spam in 5,574, but missed more than twice as much spam. It also counts *absent* words as evidence, which hurts on short messages. Multinomial gave the best F1.

**3. Smoothing.** F1 peaked at α = 0.1 (0.960) and changed by less than 0.01 between α = 0.01 and 2. Large α (5.0) pushes every word's probability towards uniform: precision rose to 0.983 but recall fell to 0.905.

**4. Why logs are necessary.** For the longest message (189 known tokens), multiplying the probabilities gives exactly `0.0` in 64-bit floating point. Adding their logs gives −1182.1.

**5. What it learned.** The tokens that most favour spam are `<longnum>`, `claim`, `prize`, `won`, `tone`, `guaranteed`, `ppm` and `<url>`. Those that favour real messages include `he`, `i'll`, `lor` and `later`, but the top two are `gt` and `lt`. They come from `&lt;#&gt;`, an HTML-escaped placeholder that replaced numbers in 214 messages, all of them real ones (none spam). So the model partly learned the dataset's anonymisation rather than language, which is worth knowing before trusting any classifier's top features.

**6. Its mistakes** (10 of 1,116 on the test split):
- The 2 real messages marked spam were about prices (`Wewa is 130. Iriver 255. All 128 mb.` and a message listing `$140`, `$180`, `$900`), exactly the features spam relies on.
- Of the 8 spam messages missed, 6 contain none of the 20 strongest spam tokens; they read like ordinary chat. Several are adult-content messages, so the report summarises them instead of quoting them.

## Testing

```bash
python3 -m pytest -q        # 14 tests, about 2 seconds
```

- **Textbook check:** the multinomial and Bernoulli probabilities and class scores match Examples 13.1 and 13.2 of Manning, Raghavan & Schütze, *Introduction to Information Retrieval*, exactly (computed with `fractions.Fraction`). The test also checks that the two variants disagree on that example, as the book shows.
- **Reference check:** both models match scikit-learn on the real data, at two values of α.
- **Quality floor:** precision and recall above 0.93 in cross-validation. This catches changes that keep the code running but quietly ruin the model.
- **Behaviour:** unseen words ignored, smoothing keeps probabilities above zero, `predict_proba` sums to 1 and stays finite for a 4,000-token message, invalid settings rejected.
- **Helpers:** the tokenizer, metrics computed by hand, stratified folds (disjoint, complete, same spam ratio in every fold, deterministic per seed), TSV loading errors, and the CLI.

Nine bugs were planted one at a time:

- wrong smoothing denominator (multinomial);
- wrong smoothing denominator (Bernoulli);
- Bernoulli ignoring absent words;
- class priors ignored;
- no log-sum-exp;
- unseen words not filtered;
- folds not stratified;
- long numbers not grouped;
- false positives and negatives swapped.

All nine are caught. The swap got through at first: the hand-made example had exactly one false positive and one false negative, so swapping them changed nothing. The example is now deliberately asymmetric.

## Design decisions and challenges

- **No NumPy in the model.** Word counts are `Counter`s and probabilities are dicts, so every formula is visible in the code. Training and predicting on 5,574 messages still takes well under a second.
- **Proving correctness two ways.** A from-scratch implementation is only convincing with a reference. A textbook example checks the formulas exactly, and scikit-learn checks them at scale. To compare fairly, `compare.py` feeds both the identical feature matrix.
- **Evaluation hygiene.** The vocabulary is built only from each training fold. Building it from all the data would leak information about the test messages. Splits are stratified, because a fold with fewer spam messages would give an unfair score.
- **Responsible reporting.** The error analysis lists harmless mistakes in full and summarises the adult-content ones.

## Future improvements

- Complement Naive Bayes, which is often better on imbalanced text.
- TF-IDF features and bigrams, compared under the same cross-validation.
- A precision–recall curve by varying the decision threshold, since a spam filter should prefer missing spam over hiding real messages.
- Replacing the `&lt;#&gt;` anonymisation placeholder with `<num>`, then measuring how much the scores depended on it.

## What this project teaches

- The maths of Naive Bayes, and how it becomes code: priors, likelihoods, smoothing, log space and log-sum-exp.
- The difference between the multinomial and Bernoulli event models, shown on a textbook example and on real data.
- Evaluating a classifier properly: baselines, precision and recall, stratified cross-validation, and reading the actual mistakes.
- Feature engineering: a better tokenizer improved results more than the smoothing setting did.
- Verifying an implementation against an exact hand-computed case and against a trusted library.
